# PlanDoSee

계획, 할 일, 실제 실행, 돌아보기를 한 흐름으로 관리하는 개인 플래너입니다.

## v1.0.0

첫 공개 버전입니다.

PlanDoSee는 **계획을 중심으로 할 일과 실행 기록을 연결**합니다. `계획` 화면의 왼쪽 목록에서 계획을 선택하면 오른쪽 작업 공간에 그 계획의 상세 정보와 연결된 할 일이 함께 나타납니다. 수정 이력은 메인 화면을 차지하지 않고 필요할 때 `수정 이력` 버튼으로 열어 확인합니다.

### 주요 기능

- 계획의 기간, 우선순위, 성공 기준, 예상 시간을 관리합니다.
- 계획이 하나도 없을 때는 첫 계획 생성 화면만 표시하고, 계획이 생긴 뒤에만 할 일 관리 영역을 표시합니다.
- 계획을 수정하면 이전 버전을 그대로 보존하며 수정 이력은 필요할 때 모달로 확인합니다.
- 선택한 계획 안에서 할 일을 생성·수정·완료·되돌리기·삭제할 수 있습니다.
- 마감일, 우선순위, 태그, 예상 시간과 검색·필터·정렬을 지원합니다.
- 실제 실행의 시작 시각, 종료 시각, 실제 소요 시간, 막힌 이유를 별도로 기록합니다.
- 완료·지연·막힘·예상 시간·실제 시간·차이를 돌아보기에서 집계합니다.
- 집계 숫자를 눌러 해당 숫자의 근거 기록을 확인할 수 있습니다.
- 돌아보기에서 정한 개선점을 다음 계획으로 이어받을 수 있습니다.
- 월간 캘린더에서 계획 기간, 할 일 마감, 완료·지연, 실행 기록을 확인할 수 있습니다.
- 돌아보기를 전체 계획 / 이번 주 / 지난 주 / 이번 달 / 직접 지정 기간으로 조회할 수 있습니다.
- 모든 자료를 JSON 파일 하나로 내보낼 수 있습니다.
- 실제 데이터는 Supabase PostgreSQL에 저장하고 브라우저는 Vercel Functions를 통해 접근합니다.

샘플 데이터는 포함하지 않습니다. 처음 실행하면 직접 계획을 만들고 실제 할 일과 실행 기록을 입력하는 구조입니다.

## 구조

```text
Browser
  -> Vercel Functions (/api/*)
      -> DATABASE_URL
          -> Supabase PostgreSQL
```

브라우저 코드에는 데이터베이스 비밀번호나 서버 비밀키를 넣지 않습니다.

## 주요 파일

```text
index.html
style.css
script.js
api/
lib/
database/schema.sql
contracts/pds-schema-v2.json
SUPABASE_SETUP.md
REQUIREMENT_STATUS.md
```

## 실행 순서

1. GitHub 저장소에 이 소스를 올립니다.
2. `SUPABASE_SETUP.md`를 따라 Supabase 프로젝트와 테이블을 준비합니다.
3. Vercel 프로젝트에 `DATABASE_URL`을 등록하고 배포합니다.
4. `/api/health`에서 데이터베이스 연결을 확인합니다.
5. 실제 계획 1개 이상, 할 일 5개 이상, 실행 기록 3개 이상을 직접 입력합니다.
6. `REQUIREMENT_STATUS.md`와 요구사항 체크리스트를 기준으로 최종 동작을 검증합니다.

브라우저 저장소는 실제 데이터의 원본으로 사용하지 않습니다.
